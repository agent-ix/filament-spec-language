# NFR-141: Measure performance-program paths with repeatable benchmark axes

## Statement

For each performance-program change listed below, the benchmark suite SHALL run
the named workload, report its specified measurements, and compare the candidate
with current `origin/main` using live A/B measurements from the same session.

## Scope

This requirement covers the measurement and comparison criteria for QSL-1919,
QSL-1921, QSL-1922, QSL-1923, QSL-1924, QSL-1925, QSL-1926, QSL-1927 and
QSL-1930. It does not set a numeric speedup target where the corresponding
ticket explicitly says that stored numbers are not thresholds. The current
repository's benchmark guide is `fsl-bench/BENCHMARKING.md` (the QSL-1919
description refers to `qsl-bench/BENCHMARKING.md`).

## Rationale

These tickets identify distinct workloads and comparison obligations. Naming
the axes, generators, units and decision boundaries makes each before/after
result reproducible and keeps a benchmark from silently changing the workload
it claims to measure.

## Measurement and Evaluation

| Metric | Target | Threshold | Method |
| --- | --- | --- | --- |
| Package emission and read cost (QSL-1919) | Named `package/emit` and `package/read` axes, each using checked fixtures with M timed models at M = 1, 10 and 100; report wall time per operation and the scaling exponent in M. Each axis is selectable by name and listed in the benchmark guide with its unit and input generator. | Run and report all three M values and the fitted exponent. The ticket specifies no fixed numeric wall-time or exponent limit. | Five-round live A/B benchmark comparison |
| Replay request cost and parsing (QSL-1919) | Named `replay/request` axis for one replay request end to end; report wall time per request, peak RSS, and parse calls per source document. | Run and report each of the three metrics for the live A/B runs. The ticket specifies no fixed numeric performance threshold. | Five-round live A/B benchmark comparison; peak RSS from an isolated one-shot probe |
| Evaluator child traversal (QSL-1921) | `evaluator/kernel` using `KernelCase` at sizes 5 and 10, and `evaluator/call_chain` using `linked_chain(frames)` and one call of `f0(5)`; report each axis's wall time and allocation profile, including the allocation share attributed to child traversal. | Preserve identical outcomes and charges in the existing evaluator tests; no fixed numeric timing or allocation-share threshold is specified. | Existing evaluator tests plus live A/B benchmark and allocation profile |
| Successful parser bookkeeping (QSL-1922) | `parser/volume` using `volume_source(functions)` and `cst/parse` using the `nested_source(depth)` inputs at depths 0..=4 plus `volume_source(1000)`; report wall time for each named workload and retain parser-corpus tree and diagnostic comparisons. | Trees and diagnostic text, including expected-set order, are identical; the ticket specifies no fixed numeric timing threshold. | Parser-corpus comparison plus live A/B benchmark |
| Default grammar construction (QSL-1923) | `parser/depth/0` generated by `nested_source(0)`; report wall time for the ticket's 150-byte input shape and compare trees and diagnostics. | Trees and diagnostic text are identical; the ticket specifies no fixed numeric timing threshold. | Parser output comparison plus live A/B benchmark |
| Enum-member lowering (QSL-1924) | `checker/enum_members`, generated by `enum_members(1000, binding)` for 10, 100 and 1,000 members; report wall time and the scaling exponent from 100 to 1,000 members. | Checked output is identical, and the measured exponent from 100 to 1,000 members is no greater than 1 plus the session-noise allowance computed from the live A/B observations. | Checked-output comparison plus live A/B scaling benchmark |
| Checker hashing and ranking (QSL-1925) | `checker/chain` from `call_chain(functions)`, `checker/independent` from `independent(functions)`, `checker/text_cluster` from `text_cluster(records)`, and `checker/object_chain` from `object_chain(types)`; report wall time and scaling exponents for each axis. | Checked output and node keys are identical; the ticket specifies no fixed numeric timing or exponent threshold. | Checked-output comparison plus live A/B benchmark |
| Parser/CST and checker memory (QSL-1926) | `parse-volume 200000` generated as 200,000 one-line functions (12.9 MB source) and `check chain 8000` generated by `call_chain(8000)`; report peak RSS for each and a heap profile naming the largest per-node contributors. | Post the heap split to QSL-1926 and report peak RSS for both workloads before and after; the ticket specifies no fixed numeric RSS limit. | Heap profiling and isolated live A/B peak-RSS probes |
| Type assembly and normalization (QSL-1927) | `bench-model` generated with widening redefinitions and package-typed fields at 1,000, 4,000 and 16,000 types; report the before exponent, then the after exponent if a super-linear cause is fixed, or the measurement table if growth is linear. | If growth is super-linear, fix the cause and show identical outputs and the after exponent. If growth is linear, close with the complete three-size table. No numeric exponent threshold is specified. | Live A/B scaling benchmark and output comparison |
| Workspace build time (QSL-1930) | Report wall time for cold and incremental `cargo build --timings` and for `cargo test --no-run`, before and after the change. | Record all three comparisons; the ticket specifies no fixed numeric build-time threshold. | Live A/B build measurements |

## Verification

The benchmark guide names each axis, its generator, its size inputs and its
unit. Every result records all requested workload sizes and metrics for both
sides of the live A/B run. Where a ticket gives an explicit correctness or
scaling boundary, the result checks that boundary; where it says no stored
numbers are thresholds, the result reports the measurements without inventing
a fixed numeric performance gate.
