Caller-supplied scalar accounting could not reach the coordinated run entrypoint, and source verification plans ignored caller clocks, compile-stage limits and observation limits. The public `RequestOverrides` now carries `accounting: Option<&filament_exact::ScalarLimits>`: the caller's fully resolved effective scalar budget. Drivers borrow their existing `Call.accounting` while request function, arguments and object world remain request-owned.

Source/package calls and item-generated call/clause requests use that exact budget through their existing readers. Source plans use the normal clock override reader and caller `SpineLimits`, and pass scalar accounting and observation limits into their existing analyze coordinator. Existing duplicate-clock refusals and typed budget failures are preserved.

The public execution signatures remain `run_with_limits_and_overrides` and `run_with_providers_and_limits_and_overrides`; callers add the accounting borrow to the same `RequestOverrides` already passed to either entry. The driver's existing limit application changes SpineLimits and Call.accounting; its supplied-value limits remain at their existing default.

Validation: two new named public-API acceptance tests pass with `--test-threads=1`: `caller_overrides_reach_call_and_items_accounting` and `caller_overrides_reach_plan_clocks_stages_and_observations`. They cover successful controls, caller scalar limits in calls/items/plans, S1 stage limits, initial observation limits, and duplicate clocks. Actual receipts and original fixture failures are in [.agent/qsl-2760-focused-receipts.md](.agent/qsl-2760-focused-receipts.md). No full test suite or final integration gate was run.

Remaining work: QSL-2760 stays open until the real driver adopts this forwarding API. Replay-context capture and reference dispatch remain with their existing owners.
