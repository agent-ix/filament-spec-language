## Summary

Ticket: QSL-2240 (slice S3, branch qsl-2338-s3-automaton). Reviewed `git diff origin/main...HEAD` against FSpec FR-418 and FR-419 at FSpec origin/main, the design in fr418-design.md, and arch rulings U6 and U7. The pre-miss lowering is faithful. The service-clock encoding is sound before a miss because relative job order is static under both policies, so jobs nest like a stack. EDF diagonals have the right orientation and tie strictness. Scheduler exclusivity is miss > complete > preempt > dispatch/resume. Overflow is data, policy comes from the plan, and U6 refuses dual-WCET sets with mode switches. Two problems block the PR. First, post-miss successors under-approximate the concrete product and can create spurious time-locks, which FR-418's locked-miss rule then reads as soundness evidence. Second, the U7 condition (a meaningful cross-check) is not met for jitter or for edge labels.

## Scope and evidence

Examined, with these results:
- FR-418 task-automaton certificate text (:96-112, :121-151, :153-215).
- FR-418-AC-12, AC-13, AC-18..21.
- FR-419 task-automata semantics: activation spacing, jitter, miss, ties, the fixed-work bounded-subtraction construction.
- Clock order (FR-418 :153-155) matches `auxiliary_clocks()`.
- Ranking: deadline-clock age then generation. The new job is appended last in its task's list. Same-instant ties are impossible under spacing T > 0.
- EDF `before` atom `d_r - d_l <(=) -(D_l - D_r)` is correct. Ties go to the smaller canonical task name; same-task jobs order by age.
- Miss guard: `d >= D`, plus `s < W` for the running job. Pending jobs miss with their full demand.
- Exclusivity chain: miss_i ∧ ¬miss_<i, complete ∧ ¬miss, preempt ∧ ¬miss ∧ ¬complete, dispatch ∧ ¬miss.
- Delay urgency: urgent actions become enabled only at invariant endpoints.
- Coder's open choices:
  - (a) Service clock reset at first dispatch, minus W on completion, and preempt-with-zero-service back to unstarted: sound before a miss (stack nesting; every completing job's full W accrues on each started worse job).
  - (b) Post-miss states not exact: unsound for FR-418's locked-miss rule (FND-001).
  - (c) Miss tie-break: unspecified, needs a ruling (FND-005).
  - (d) Release non-urgent: sound (nondeterministic jitter in [0, J], invariant `j <= J`).
  - (e) Spacing guard in the source guard: sound (periodic `x = T`, sporadic `x >= T`, invariant `x <= T`).
  - (f) Two releases of one task by one operation: unreachable (DuplicateRelease), low (FND-006).
  - (g) Jitter only tested structurally: medium (FND-002).
- The three task_product.rs changes (`arrivals()`, `pub(super) job_order`, `pub(super) source_clock_maxima`) are minimal and correct.
- No `#[allow]` and no digest in the diff. No `unwrap`/`expect`/`panic!` outside tests; the remaining panic surface is index arithmetic (FND-008).
- Tests run: 7/7 task_automaton_crosscheck pass. The run used the temporary uncommitted monitor_root.rs patch (`Some(..)` wraps plus `member_type: None, collections: Vec::new()`), which was reverted afterwards.

Failure scenario for FND-001: a fixed-priority set with x (priority 1, periodic 6, D 2, W 6) and y (priority 2, periodic 10, D 5, W 1).
1. y activates at 0 and is dispatched.
2. x activates at 0.5 and preempts y. y's service clock is 0.5 and y is started.
3. x misses at 2.5 and `missed` latches.
4. At 6.5, x reaches s = W. y's service clock is 6.5, above its ceiling max(1, 5) = 5, so the subtraction range fails and `fire` returns None.
5. Complete is in `urgent`, so no delay is admitted, and the x re-activation source edge leads to the same blocked state. The automaton is time-locked.
6. The concrete `TaskProductSystem` completes x and lets time diverge (y resumes).
7. Under FR-418 (:226-228) and design step 5, the checker would accept the miss node as `locked` with no reachable divergent target and settle `proved`.

The cross-check stops at the first miss (task_automaton_crosscheck.rs:120-122), so it cannot detect this.

## Verdict

Not mergeable. FND-001 (high) needs a code fix or an explicit arch ruling. Either make the lowering refuse or flag post-miss locations so the checker never treats a reachable miss as locked-without-divergence, or rule that a reachable miss node never permits `proved` in v1. FND-002 to FND-004 are needed to meet the U7 cross-check condition. Everything else in the lowering is faithful to FR-418/FR-419 on pre-miss paths.
