## Summary

Ticket: QSL-2935. Spec-only PR, reviewed as `git diff origin/main...HEAD` at e25a201bf28cfa58f9d68a23d94a697c59797ec4; quire validate over the five touched files exits 0. No cargo was run.

Checked FR-1047 for unstated failure modes and inputs. Checked whether its ordering rule is deterministic and whether its missing-member rule conflicts with readers that already have their own missing-member refusals. Also checked the run entries' non-envelope inputs and the precedence between defects.

## Findings

| FND-001 | medium | 'Example order' is not deterministic. (a) FR-1047 never states the member order of an example. AC-1 (models, program, call) and AC-4 (authority, identity, document, formal_revision) imply it. The workspace serde_json has no preserve_order (Cargo.toml:93), so an example built with json! would order its members alphabetically (call, models, program; authority, document, formal_revision, identity) and fail AC-1 and AC-4. (b) FR-1047 requires missing members 'at every depth', but it gives no position to members the example does not hold. These include array elements (/request/models/0/source, since the example's models is []), the other alternative of a group (/request/package/..., /request/clause/..., /request/items/...) and optional objects the request carries (/request/libraries/0/...). Fix: define the order as each reader's declared member order (the order the example uses), with document order for array elements. | spec/functional/FR-1047-name-every-request-defect-and-return-a-request-example.md:99-106 |
| FND-002 | medium | run_configured also admits documents that are not request envelopes. version_argv (FR-661) and check_argv (FR-562), at command.rs:2130-2300, run {"argv":[...]} documents that carry no format and no request. FR-1047's rule that 'a document lacking format or request lists only /format and /request as missing' applies to every run entry, so it would refuse those documents. Fix: exempt documents with argv, or state that those adapter documents are not request documents. | spec/functional/FR-1047-name-every-request-defect-and-return-a-request-example.md:127-129 |
| FND-003 | medium | FR-1047 requires every missing member, 'at every depth', to be refused invalid-request with pointers from the document root. The export and export_evidence readers refuse a missing nested member as invalid_runtime_input/missing-member at a pointer relative to the member: export/request.rs:171 gives /profile (FR-1015), and evidence.rs:40-48 gives /export_evidence/package (FR-1022 also states /export_evidence/...). FR-1047 does not amend or carve out these readers. Since it says the members' rules 'stay with the requirement that owns the format', the code and pointer for /request/export/profile are contradictory. ## Verdict

Three medium findings and two low ones. The ordering rule cannot be implemented deterministically as stated. The every-depth rule conflicts with the export and export_evidence readers. The rule for a document with no envelope would refuse run's argv adapter documents. Mergeable once the medium findings are fixed.
