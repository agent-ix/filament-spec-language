# SR-2026112100430301: code-review of PR 3232

## Summary

Ticket: QSL-2240 (the PR title and body name QSL-2240; the branch name `qsl-2338-s1-codec` names an unrelated ticket). PR agent-ix/filament-spec-language#3232, head 657f69b983. This review includes the rust-review lane. The PR adds a strict JSON reader and writer for the FR-418 `task_product` member and `TaskTransitionTemplate`, typed shape refusals mapped to `malformed` at `{member: task_product}`, and a `TaskProductKey` type for a task-product node's `s`. The `:857` guard in `check_zone_certificate` is untouched. The reader's member, kind, enum, closure and cap checks are correct. The key is a second, divergent encoding next to fsl-eval's `TaskProductSystem::state_key`, which the arch ruling U2 forbids. The source-transition codec does not round-trip a checked model transition.

| FND-001 | high | Ruling U2 asks for one encoding, shared with `TaskProductSystem::state_key`. `TaskProductKey::octets` is a second encoding in a second crate, and its grammar differs from that function's. It has no per-source-place clock fields after the source hex. Its job token is `task:rank:slot:allow:phase:release`, where state_key writes `task:slot:demand:jitter:deadline:service:allow:r/p:x/-:release`. It adds a `|q` queue section. A pending change is `:task@rank:` here and `:task@slot#gen@occ:` there, and state_key does not sort pending changes. The module doc says it "uses that key's token grammar", which is not true. The test asserts only its own spelling and never compares with state_key. The type lives in fsl-replay, and fsl-eval cannot depend on fsl-replay. So the S3 lowering in fsl-eval (locations = source discrete state x scheduler control) cannot call it, and S3 and S4 cannot share one function. The content change (no rationals, ranks, queue order, rank-keyed pending changes) is sound for zone nodes. The defect is the second place. Fix: put one scheduler-control token writer in fsl-eval beside state_key and call it from both encodings, then add a test that compares the two on a shared state. ## Scope and evidence

FSpec FR-418 at filament-specification origin/main cd89fcb3 (identical to the FSPEC-QSL2653 checkout; only schema.json differs, and not in these definitions). Read fully, including :60-69, :96-134, :136-150, :152-169, :171-195, :277-306 and AC-7, AC-8, AC-9, AC-11, AC-13 and AC-14. Also read the schema definitions TaskProductCertificate, TaskTransitionTemplate, TaskTransitionIdentity, SourceTransitionIdentity, CertificateTransitionIdentity, Count/PositiveCount, and checked-package-v2 Rational/IntegerString/PositiveIntegerString, the design /tmp/fr418-design.md, fsl-eval TaskProductSystem::state_key/lasso_state_key, fsl-replay planner read_task_search, task_source_transition_wire and state_key_wire.

Checked clean:

- Unknown or missing members are refused at every object level, including `time_progress`, queue rows, ceilings, diagonals, subtractions, templates, source transitions and rationals.
- Wrong kinds are refused, and so are counts outside 0..2^53-1, floats, and integer strings that are not canonical (filament-exact `parse_unlimited` refuses `+`, leading zeros and `-0`).
- Rationals must be in lowest terms with a positive denominator. Enum spellings for actions, methods, closures, arrivals and operators are refused when unknown.
- Policy-like members are refused as unknown at every level. A template never carries job, generation, demand, jitter, deadline or budget_delta.
- Method/closure/cap coherence is enforced both ways. Empty `queue_bounds` is refused. Under no-release, ceilings, diagonals and subtractions must be empty.
- Every shape refusal maps to `malformed` at `{member: task_product}`. Key invariants refuse an unknown task, non-dense ranks, a shared slot, more than one running job, a queue that is not exactly the ready jobs, and a dangling budget change.
- The diff has no digest, hash or checksum and no `#[allow]`. It has no panic path outside tests. The zone_certificate.rs `:857` guard is untouched (empty diff on that file).
- Tests: `cargo-slot cargo test -p fsl-replay --lib certificate::task_product -j 4 -- --test-threads=1 --skip ... --skip ...` result: 12 passed, 0 failed (1472 filtered out) at 657f69b983. The assertions name exact variants and pointers, so they can fail.

## Verdict

Not mergeable as is. FND-001 is high and conflicts with ruling U2. Fix it in this PR, or get an explicit arch re-ruling, before S3/S4 build on the key. Fix FND-002 to FND-004 in this PR too. They are cheap now and each one makes S4 reject a valid certificate or accept a non-canonical key. The wire reader is otherwise strict and correct for AC-11 and the AC-14 shape.
