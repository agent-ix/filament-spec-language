## Verdict

Request changes at cf9b9048e2 for FND-001 only; FND-002..004 are low and do not block once FND-001 is fixed and the monitor family is re-run at the final head.

The #3916 walk change is correct and matches FSpec FR-825 ("In this walk, `if` then/else branches contribute their condition with `holds` true/false; the right operand of `and`, `implies` and `or` contributes the left operand ..." with no literal exception) and the pinned reader (contract-ir 842b4dc59, #1172). The walk differs from main's only where a guard operand is a reference to a `value` node with a Boolean literal body inside a body walk (derive=true); every other unit walks identically. The checker (fsl-semantics check/claims.rs `Classify::claim`) already records claims and literal guards on the decided-away side, so the record set is unchanged.

The #3916 review record exists (QSL-3283 comments dc81e37f SR-18141978327025, eb0f4cb5 SR-57370951109817 at 63b738f8f3, the same commit merged here by e5a83eee1c). Its FND-001 (not mergeable alone, needs a reader with #1172) is now met by the fcefa8460e pin, which contains 842b4dc59. Its FND-002 (FR-356-AC-7 acceptance) has a lead decision (58a9ed9f). The earlier QSL-3120 reviews (f387a198, 60901859) had no findings; the QSL-3120 hunks are unchanged, so they stay valid.

Monitor reds: the change makes no unit that works on main fail on this head. Main's 32 RequirementRowCarry and this head's SourceMapInvariant are the same underlying fault, a checker expression occurrence with no source-map entry (QSL-3314). The probe shows main's walk stopping at the same `ordinals.rs` `apply` lookup, on the same node and ordinal, for the other 7. The full walk now renumbers nodes that main's pruned walk left on the identity mapping, so those units reach that lookup before the rekey check. Outside monitors, a unit with that fault cannot have worked on main either: the node keeps an occurrence with no entry, and the strict reader refuses that (contract-ir FR-038-AC-605, "an occurrence without an entry at `/source_map` ... `invalid_source_map`"). So the refusal moves from read to write. Residual: whoever fixes QSL-3314 must verify the 32 against this walk, because the earlier failure now hides the later rekey check.

Event projection: not a regression and not an FSL writer defect. Main's pin (b81baf1441) refused an event-typed parameter node outright (IR-1615 admitted it at 1066b054c), so every package with a clause over an event subject was refused on main. This head admits `holds(true)` over it and refuses only operations over event values. contract-ir #1177 refuses `filament.op.record.project` over an event value on purpose, against FSpec TC-281 EV-03. FR-038 records this divergence and cites STD-728, and FSL follows FSpec. It is not fixed in this PR. It needs an upstream ticket (IR, or an STD ruling if FSpec should change), using 3807-probe-event-projection.diff/.log as the failing test. STD-728 covers only binder typing, and no ticket for the projection was found.

Red `a_model_bearing_unit_emits_its_model_selection_and_reads_back_verified`: introduced by QSL-3232 #3856 (cf6b08697b appends `model_correspondence::append` after the model roots, so the test's "model_root is last in graph order" assertion fails; kept by #3886). This is inferred from the diff and the identical assertion on main 4baf455edb (tests.rs:3387) and on this head (tests.rs:3389). It is not this PR's to fix. File a defect/regression ticket with the line "Introduced by: #3856 (inferred)"; none was found.

The other reds are the same on main: protocol_owner_edges (QSL-3281, the same panic at checked_term_protocol_rows.rs:210) and compact_composite_bodies (QSL-3319, the same refusal at /semantic_graph/nodes/9/occurrences). The fsl-replay hybrid_replay/class.rs dead-code clippy errors are in a file identical to the merge base, and the touched crates pass clippy with `--no-deps`.
