## Verdict

**FAIL. One fix round is needed: one high, one medium and two lows.**

What is correct:

- **QSL-2722 layer gate.** `visit_located_operators` passes `spans.operator_span(id)`. Only `Binary` nodes get an operator span (fsl-forms/src/value.rs:1766), and the only binary operators `expression_form` refuses are `div`, `rem` and `mod`, so the relocation reaches nothing else. Declaration-level refusals do not change, because `declaration()` runs before `expression()`. The model gate (model_gate.rs), probabilistic.rs and refinement.rs keep using `visit_located` and are unaffected.
- **QSL-2693 classification.** `extension_catalog_cause` maps only `PackageError::UnknownCapability` to the new cause, so every other catalogue failure stays `InvalidPackage`, as the ticket requires. `Code::UnknownRequiredFeature` is in `is_unsupported`, so the exit is 21. The outcome-document arm and the stage (`Spine(Forms)`) match `ExtensionCatalog`. The match is exhaustive and has no wildcard.
- **QSL-2702.** The production fix is already on main (#3212). AC1 to AC3 are covered by `a_returned_counterexample_rejects_a_different_real_post_state_as_content_mismatch`, `terminal_predicates_do_not_turn_enabled_states_into_early_terminal_states` and `model_settle.rs::a_counterexample_the_model_does_not_take_refuses_with_no_result`, which has the exact `PostState{step, recorded, reached}` and `NotEnabled` assertions.
- **Rust idiom.** The changes are small and typed. There is no `unwrap` in production code and no wildcard. The doc comments say why. The `visit_located` delegation wrapper keeps its existing callers unchanged.

## Findings detail

- **FND-001.** `layer_refusal` asserts `&text[error.span.start..error.span.end] == located`. The test passes `"x div 2"` and `"x rem 2"` for `predicate ... using q`, which is state.queries. That layer does not admit `ValueConstruct`, so `LayerAdmission::expression` refuses the `IntegerDiv`/`IntegerRem` binary node. It now uses `operator.unwrap_or(span)`, and because the node was read from source its operator span is `Some`, so the located text is `div` (or `rem`) and the assertion fails. Scenario: `make ci` or any full `fsl-semantics --lib` run goes red on merge. **Fix:** change the expectations to `"div"` and `"rem"`, and update the doc comment ("at the expression") to say at the operator. FR-495-AC-4 says the operator is located "at its own span", and the change applies to every layer, which is consistent. Confidence high: traced statically; the confirmation run was queued and had not finished.
- **FND-002.** FR-111 Bundle says "a capability outside the inventory SHALL refuse `unknown_required_feature`/`unknown-feature`", and the Refusals table row repeats it. In output.rs `error()`, the `cause:` match has no arm for `UnknownExtensionCapability`, so `_ => None` applies. The `OutcomeDocument` path in command.rs passes `None` too, since only `IntegerDivisionLaw` gets a cause. The library already carries the tag (fsl-semantics/src/library/bundle.rs:925 maps `UnknownCapability` to `Tag::UnknownFeature`). Scenario: a client that reads the `native-compile/1` failure's `cause` for the unknown-feature row gets `null`, and cannot tell it from the `unsupported-feature` row (a missing inventory capability), which has the same code. **Fix:** return `Some("unknown-feature")` for `UnknownExtensionCapability` in both places. Extend the test to assert the rendered failure's `cause` and the exit category (21).
- **FND-003.** The `assert_ne!` does separate an implementation that follows the recorded key from one that ignores it, whether it always takes the first successor or always the returned one. It is still indirect: a replay that took another successor and settled differently for an unrelated reason also passes, and nothing shows that `taken` reproduced the deadlock. **Fix:** assert `taken.settlement` is `Reproduced { value: Truth(false), .. }`. Then assert the concrete settlement of `result`: the truncated prefix ends at value 2, where `inc` is still enabled, so by FR-128-AC-2's analogue it is the not-reproduced/parity arm. Or assert the reached state's counter value is 2.
- **FND-004.** **Fix:** retag to `#[trace("FR-128-AC-1")]` (or add it), so the matrix binds AC-1's multi-successor clause.
