## Summary

Spec review of PR #3088, which applies spec work item SW-1 from ruling comment e1f295bd on QSL-2534. The PR text matches SW-1 word for word, plus a rationale sentence. The review checked it against filament-specification origin/main: FR-193 "Continuous values and expressions" (lines 201-234), "Resets" (236-258) and "Exact replay" (737-798), the shared-grammar `hybrid-decl` (lines 848-855), and the `unsupported_construct` row of `native-diagnostics.md` (line 62). Ticket: QSL-2534. `quire validate` on both changed files passes.

## Examined scope

- Class versus FSpec FR-193. FR-193:209-217 admits `/` as a rational term in the language. That is a language rule, and a provider class may be narrower than the language, so there is no contradiction. FR-193:741-743 defines a polynomial flow syntactically, as built from constants, variables, unary `-`, `+`, `-` and `*`. Under that definition `x / 2` is not polynomial, while `rational(1, 2) * x` is, because FR-193:205-206 makes `rational(n, d)` and decimals constants. So the ruling is consistent with FSpec for flows. For guards, resets, invariants and initial conditions the exclusion is a design choice, not something FSpec forces, and the stated rationale overreaches (FND-003). (examined)
- Source order versus the grammar. `hybrid-decl` puts `[hybrid-initial]` before the modes, and `hybrid-mode` is `invariant`, then `flow`, then `transition ... when block reset block` (shared-grammar:848-855). The ruled order follows the grammar. (examined)
- AC-14 rows against the pre-order rule, using `examples/hybrid-braking/braking.native` as the base. The Moving invariant is inside the class and Braking has no `initial` clause. Row 1 is located at the initial `/`, mode `Moving`; the initial entries come before the flows. Row 2 is located at the outer `/`, whichever way unary minus parses. Row 3 is located at the `if`. Rows 4 and 5 are inside the class. Every row can fail. (examined)
- The refusal cause exists. `unsupported_construct` with `expression-form` is in the closed catalog (native-diagnostics.md:62). (examined)
- Ids. FR-1019-AC-14 is not on origin/main. Open PR #3085 changes no spec file, and its `ref-3b`/`ref-3c` strings are request labels, not TC step ids. The `3b.` substep form already exists in TC-454 and TC-1043. TC-2869 now scopes AC-1 to AC-12 plus AC-14, and AC-13 stays with TC-2997. (examined)

## Verdict

Not mergeable yet. There are three medium findings and two low ones, and all of them are wording fixes inside this PR. The ruling itself is consistent with FSpec FR-193, FR-331 and the grammar.

Context outside this diff: PR #3085's `class.rs` walks the initial entries after the modes, and it tags its guard-division test FR-1019-AC-3. Once this PR lands, #3085 must reorder the walk and tag AC-14.
