## Evidence and required changes

FND-001: For `{"format":"native-run/1","request":{"models":[],"export":{"profile":"filament.output.tla2/v1","obligations":["Low"],"z":ARRAY}}}`, ARRAY is 16,000 opening brackets, `0`, then 16,000 closing brackets. This is below the default request-byte bound. request::read returns unknown-member for z, then the removed member is recursively dropped. Preserve iterative ownership/disposal for every detached tree and inspect the adjacent recursive package clone/serialization paths under the same new unbounded-depth admission. Add a subprocess regression asserting a typed refusal and no abort. The control demonstrates the full-tree Deep owner handles the same depth correctly.

FND-002: Pinned FSpec FR-272 line 108 requires a capability payload for this cause. OutcomeDiagnostic::new currently writes only code/cause/message plus generic fields; its struct has no capability field. The local closed diagnostic schema likewise does not declare capability, which explains why the integration schema check passes the incomplete document. Provide the required named capability through the typed lifecycle owner and its matching closed schema/catalog contract; keep schema validation strict and add a payload oracle. This does not request genuine proof settlement.
