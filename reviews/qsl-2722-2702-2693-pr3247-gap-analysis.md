## Findings detail

- **FND-001.** For `1 + 7 div 3 * 2`, the parser builds the chain links root first and zips each link with its operator token (value.rs:1759). An off-by-one in that zip would put the `*` or `+` token on the `div` node. The test as written cannot detect that, because a single-link chain has only one token. **Fix:** add AC-4's three state-only bodies verbatim to the clause loop for `invariant`, `pre` and `post`, each asserting the located text is the refused operator.
- **FND-002.** **Fix:** add an AC (for example FR-660-AC-n: an `extensions` entry whose `capabilities` names an id outside the closed inventory refuses `unknown_required_feature`/`unknown-feature`, exit 21, while a malformed definition stays `invalid_package`), and retag the test to it. If the lead prefers, this can be a spec-steward item; it does not block the code.
